# Kubernetes 学习计划

这是一条约 8 周的路线。每周可以按自己的节奏拆成多个短时段；完成标准以“能解释、能操作、能排查”为准，不以看完视频或记住命令为准。

## 总目标

能够在隔离的练习集群中部署一个小型 Web 应用，理解它从配置到运行的过程，并能使用 `kubectl` 定位常见故障。

## 阶段安排

| 阶段 | 主题 | 动手成果 | 完成标准 |
| --- | --- | --- | --- |
| 0 · 准备 | 容器、镜像、YAML、Linux 网络基础；选定隔离环境 | 本地命令行工具就绪，环境信息有记录 | 能说明容器与 Pod 的关系，确认练习不会影响其他业务 |
| 1 · 核心对象 | Cluster、Node、Namespace、Pod、Label、Selector | 运行并检查一个 Pod | 能查看状态、日志、事件，并解释 Pending / Running / CrashLoopBackOff 的含义 |
| 2 · 工作负载 | ReplicaSet、Deployment、滚动更新、回滚 | 部署多副本 Web 服务并完成一次版本更新 | 能解释声明式期望状态，并完成扩缩容和回滚 |
| 3 · 服务发现 | ClusterIP、NodePort、DNS、Service | 让一个 Service 稳定访问多个 Pod | 能从 selector、Endpoints 和 DNS 三处排查访问失败 |
| 4 · 配置与健康 | ConfigMap、Secret、探针、requests / limits | 将配置与镜像分离，加入健康检查和资源边界 | 能区分启动、存活、就绪探针的作用 |
| 5 · 存储与入口 | PV、PVC、StorageClass、Ingress | 部署有持久化数据的应用并配置 HTTP 入口 | 能解释数据生命周期及入口流量路径 |
| 6 · 安全与交付 | ServiceAccount、RBAC、Helm、镜像与配置管理 | 用 Helm 安装一个练习组件，验证最小权限 | 能检查权限并安全地管理练习配置 |
| 7 · 排障与复盘 | 事件、日志、资源指标、故障注入、备份概念 | 完成一次从现象到根因的排障记录 | 复盘能让另一人按步骤重现并验证修复 |

## 每周节奏建议

1. 先用自己的话写下本周要回答的 2–3 个问题。
2. 阅读概念材料后，亲手写一份最小 YAML，而不是只复制整套示例。
3. 执行实验，记录命令和关键输出；不要把 token、密码或 kubeconfig 内容写入仓库。
4. 故意制造一个低风险故障，例如拼错 selector 或镜像标签，再用事件、日志和资源状态定位。
5. 写下“我原来以为 / 实际发现 / 下次会检查什么”。

## 暂不急着学

先不从 Kubernetes 源码、复杂多集群、服务网格、生产级高可用或自建 CNI 开始。等核心对象和排障路径熟悉后，再根据实际目标扩展。
