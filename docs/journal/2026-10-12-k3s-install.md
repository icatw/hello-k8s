# 2026-10-12 · 安装单节点 K3s

这篇记录展示一次可公开复用的安装过程。主机地址、组织名称、代理地址和业务服务均使用占位符。

## 本次目标

- 确认练习主机尚未安装 Kubernetes。
- 安装单节点 K3s，禁用默认 Traefik。
- 验证节点、API Server 和系统 Pod。

## 环境快照

- 操作系统：Linux，具体发行版和版本应以现场检查为准
- 集群类型：单节点 K3s
- 练习主机：`<练习主机>`
- 代理：`<代理地址>:<端口>`，仅用于需要访问外部源的组件
- 目标：不影响主机上已有的其他服务

## 安装前检查

```bash
command -v kubectl k3s kubeadm kubelet kind minikube
systemctl is-active k3s kubelet containerd docker
free -h
df -h /
swapon --show
ss -lntup | grep -E ':(80|443|6443|10250)\b' || true
ip route
```

重点确认磁盘、内存、端口、现有容器和网络路由。使用共享主机时，先建立影响范围和回滚方案。

## 安装命令

```bash
export http_proxy=http://<代理地址>:<端口>
export https_proxy=http://<代理地址>:<端口>

curl -sfL https://get.k3s.io | \
  INSTALL_K3S_EXEC="server --disable=traefik" \
  sh -
```

如果目标系统使用 SELinux，按发行版和 K3s 官方文档安装对应的 SELinux 依赖。不要为了绕过依赖直接关闭安全机制。

## 验证

```bash
systemctl is-enabled k3s
systemctl is-active k3s
k3s kubectl get nodes -o wide
k3s kubectl get pods -A -o wide
ss -lntup | grep -E ':(6443|10250)\b'
```

预期结果：单节点为 `Ready`，CoreDNS、local-path-provisioner 和 metrics-server 进入 `Running`，6443 和 10250 正常监听，80/443 不被 K3s Traefik 占用。

## 镜像拉取失败时

如果节点已 `Ready`，但系统 Pod 长时间 `ContainerCreating`，先看事件和镜像列表：

```bash
k3s kubectl get events -A --sort-by=.lastTimestamp
k3s crictl images
```

K3s 使用自己的 containerd，Docker 的代理设置不会自动继承。应为 K3s 服务配置代理并重启 K3s，然后再次验证系统 Pod。记录真实错误，但不要把代理凭据写入仓库。

## 当前结论

- 安装方式适合单节点学习环境。
- 禁用 Traefik 可以减少与已有 HTTP 入口的端口冲突。
- 节点 Ready 只证明控制面基础可用；还需要部署一个测试工作负载，继续验证 Service、DNS、存储和清理流程。
